# 跨进程段级续传，自建段状态文件

每个未完成文件配一份段状态，记录每个分片的 `[start, end, offset]`。进程被中断后重新运行时读取该文件，逐片从各自断点继续。

这是与现有工具的核心差异：官方 `hf` 的临时文件按进程 UUID 命名，重跑从头下载，只支持进程内的 `Range` 重试；`hfd` 靠 aria2 的 `.aria2` 控制文件做续传，但校验只比对文件大小。

## Considered Options

- **复用官方 `.incomplete`**：兼容性最好，但它是整文件粒度的半成品，多分片并发下无法表达「哪一片缺多少」，仍需额外状态。
- **文件级续传**：实现简单，但多分片场景下只能退化为单流续传，等于放弃多线程。

## Consequences

- 段状态必须原子写（写临时文件后 rename），否则中断时可能写坏。
- 需要仓库级文件锁，防止两个进程同时改写同一份段状态。
- 段状态文件的生命周期要独立于缓存清理：`cache remove` 时必须连带清理，否则留下孤儿状态。
